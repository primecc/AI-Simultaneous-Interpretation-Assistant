# 跨机器发布方案

## 结论

要让软件在更多 Windows 机器上稳定运行，需要同时满足四件事：

1. EXE 与依赖完整打包。
2. 带上必要的 VC++ 运行库。
3. 用可信代码签名证书签名。
4. 首次运行所需模型和网络依赖有明确策略。

当前工程已经完成第 1、2 项，并提供第 3 项的签名与验签脚本。第 3 项需要真实可信的 OV/EV 代码签名证书，不能靠本地自签名证书替代。

## 为什么会被 Windows 拦截

Windows 11 的 Smart App Control 会阻止无法确认安全性的应用。未签名的 PyInstaller EXE 常见会被判定为未知发布者，无法在所有机器上直接运行。

要解决这个问题，需要：

- 使用可信 CA 签发的代码签名证书。
- 使用 `signtool.exe` 对 EXE 签名。
- 使用时间戳服务保留签名长期有效性。
- 尽量保持稳定的文件名、版本号、图标和发布来源，积累信誉。

## 发布门禁

这个问题已经作为固定发布规则写入项目：正式发布不能直接使用原始 PyInstaller 产物，必须使用 `packaging/build-windows-release.ps1`。该脚本默认强制签名并验签；如果没有可信证书会直接失败，避免把未签名 EXE 当成正式包提交。

仅本机开发自测可以显式添加 `-SkipSignature`。带 `-SkipSignature` 生成的包不解决 Smart App Control 拦截问题，不能作为评审或对外发布包。

## 签名命令

先安装 Windows SDK，确保 `signtool.exe` 在 PATH 中。

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\packaging\build-windows-release.ps1 `
  -CertificatePath "C:\path\to\certificate.pfx" `
  -CertificatePassword "证书密码" `
  -SignAllBinaries
```

如证书已安装到 Windows 证书库：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\packaging\build-windows-release.ps1 `
  -CertificateThumbprint "证书指纹" `
  -SignAllBinaries
```

单独验签：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\packaging\verify-release-signature.ps1 -AllBinaries
```

## 目标机器要求

- Windows 10/11 64 位。
- 可播放系统音频的 WASAPI 设备。
- 首次运行若未内置模型，需要联网下载本地识别模型。
- 免 key 翻译通道需要网络可用。

## 离线发布策略

如果希望目标机器没有网络也能做语音识别，需要把 faster-whisper 模型目录随包发布，并让配置指向本地模型路径。

翻译如果也要完全离线，需要改用离线翻译模型或内置翻译引擎；当前免 key 翻译仍依赖网络。
