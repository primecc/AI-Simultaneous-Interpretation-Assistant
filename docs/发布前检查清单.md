# 发布前检查清单

这份清单用于防止反复出现同一类发布问题。凡是修改 EXE、打包脚本、悬浮窗、字幕层、README 或 PR 描述，都必须按这里检查。

## 必须通过

- 运行 `python -m pytest`。
- 运行 `python -m ruff check .`。
- 如果改到桌面悬浮窗，运行 `python -m pytest tests\test_desktop_overlay.py`。
- 如果重新生成 EXE 或 release zip，必须运行 `.\packaging\verify-release-signature.ps1 -AllBinaries`。
- 给评委、同学或其他机器使用的包必须通过可信 Authenticode 签名验签。

## Windows 智能应用控制

截图中的“智能应用控制已阻止可能不安全的应用”不是普通代码 bug，而是 Windows 对未知发布者/未可信签名 EXE 的拦截。

固定规则：

- 未签名 EXE 只能叫“本机自测包”。
- 未签名 EXE 不能作为评审包、正式包或“所有机器可运行”的包。
- 不允许只用 `-SkipSignature` 生成发布包。
- 如确需本机快速自测，必须显式使用 `-SkipSignature -AllowUnsignedLocalTestBuild`，并在说明中写清楚会被 Smart App Control 拦截。
- 真正解决方案是使用可信 CA 签发的 OV/EV 代码签名证书进行 Authenticode 签名，并通过验签。

## 悬浮窗与字幕回归

- 悬浮球必须可拖动。
- 字幕条必须可拖动。
- 字幕背景保持深色/灰色半透明，不遮挡过多画面。
- 悬浮球图标必须使用高清资源，圆角边缘不能失真或出现黑边。
- 退出时不能留下白框、空白窗口或需要再点一下才能退出的残留窗口。

## 文档与 PR

- README 要同步最新功能、启动方式、打包方式、依赖和风险说明。
- PR 描述要逐条记录功能变更、实现思路和测试方式。
- 如果发布包未签名，PR 和 README 必须明确写出它不能作为正式跨机器发布包。
